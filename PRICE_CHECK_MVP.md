# Fin_rez — Price Check MVP

Статус: **экспериментальная функция**, разработана в ветке `feature/price-check-mvp`. Рабочая ветка `main` не затронута.

## Назначение

Проверка цен по движениям финансовых инструментов с использованием импортированных исторических котировок. Данные клиента обрабатываются в браузере. Модуль **не использует API KASE** и не проверяет автоматически достоверность загруженного источника.

## Как пользоваться

1. Для теста без публикации скачайте файл `price-check.html` из этой ветки GitHub и откройте его локально. Нажмите **«Загрузить отчёт Fin_rez · Excel»**, выберите исходный XLSX (например, с листами «Движение ФИ», «Дивиденды», «РЕПО», «ЦБ»). Альтернатива — загрузить отчёт на опубликованном Fin_rez и открыть новый пункт «Проверка цен» после принятия PR и публикации.
2. Модуль распознаёт колонку «Цена приобретения одной ЦБ», сохраняет исходную структуру книги при экспорте, исключает денежные и служебные строки из ценовой проверки.
3. Загрузите исторические рыночные цены в CSV/XLSX. Колонки: `Дата, ISIN, Тикер, Рынок, Валюта, Цена, Источник, Ссылка` (`ISIN` либо `Тикер`).
4. Нажать «Проверить», открыть «Подробнее» на подозрительной операции.
5. В карточке указать корректную цену **на основании первичного документа**, ссылку/описание источника, причину изменения и подтвердить решение.
6. Нажать «Применить к копии». Исходный расчет Fin_rez не изменяется.
7. Выгрузить «Скачать исправленный Excel» и **повторно загрузить файл в Fin_rez** для его штатного расчета FIFO. Корректировки в рамках теста не изменяют рабочий источник без импорта.

При отсутствии реального отчета нажать «Демо-операции». Все ISIN, названия и котировки в демонстрации вымышленные.

## Правила

- Сопоставление котировки только по одинаковым дате, валюте и ISIN (или тикеру при отсутствии ISIN); для указанного рынка требуется точное совпадение. Если рынок в отчёте не указан, единственная котировка с иной заполненной площадкой показывается **только как предварительный ориентир** с обязательной ручной проверкой, без автоматического вердикта «норма/аномалия».
- Для покупки/продажи вычисляется относительное отклонение: `(цена операции / котировка - 1) * 100`.
- Порог по умолчанию 20% — **только диагностический**, не признание ошибки.
- Корпоративное событие, зачисление, списание, неизвестный тип операции: ручная проверка (цена рынка не равна автоматически себестоимости).
- Нет котировки / конфликт двух котировок: статус «Нет данных», никаких выдуманных цен.
- До применения требуется ввод цены, основания, комментария и явное подтверждение.
- Отмена последнего применения доступна из карточки; события фиксируются в локальном журнале.
- Журнал сохраняется только на устройстве в `localStorage`, не является защищенным audit trail.

## Известные ограничения

- Нет автоматической загрузки KASE/AIX/INTL, связи с сайтами эмитентов, обработки корпоративных коэффициентов, НКД, валютной конвертации.
- Реальный загруженный Excel содержит множественные операции без заполненного рынка: MVP сознательно не угадывает площадку.
- Примеры исходных данных могут иметь нулевую цену для зачисления с внешнего счёта: это флаг ручной проверки первоначальной себестоимости, а не основание подставлять рыночную цену.
- Экспорт оригинальной книги через используемую библиотеку XLSX сохраняет структуру листов и заменяемые значения, но сложные стили/объекты/метаданные необходимо проверить вручную.
- Реальная биржевая цена из пользовательского файла является **ориентиром**, а не документальным подтверждением цены сделки.
- Обработка различий времени исполнения, OTC, ликвидности и торгового режима пока не реализована.
- Пересчет FIFO, эквивалента P&L в KZT и налоговых показателей выполняется **после повторного импорта** скорректированного файла основным приложением; достоверность перерасчета требует бизнес-тестирования.
- При прямой загрузке XLSX файл не хранится в localStorage и потребуется повторная загрузка после обновления страницы; история решений привязывается к отпечатку отчёта и сохраняется локально.
- Файл пользователя не публиковался в репозитории GitHub, туда добавлены только исходный код и инструкции.
- Есть зависимость от CDN-библиотеки SheetJS (такая же, как в исходном Fin_rez).
- Данные между вкладками доступны через одно происхождение (origin). Если открыть файл отдельно (через `file://` или другую платформу), данные из существующего сайта Fin_rez не подхватятся; используйте демо.
- До слияния PR обновленная кнопка недоступна на основном сайте.

## Базовые тесты

| № | Сценарий | Ожидаемое |
|---|---|---|
| 1 | Покупка 45 000 KZT против ориентира 450 KZT | Аномалия +9900% |
| 2 | Продажа с отклонением менее 20% | «В пределах» |
| 3 | Сплит при большом ценовом отклонении | «Ручная проверка» |
| 4 | KASE в отчете, AIX в котировке | «Нет данных» |
| 5 | Два совпадающих рыночных источника | «Нет данных» из-за конфликта |
| 6 | Применить к копии | Новая цена в выгрузке; оригинал в Fin_rez не изменяется |
| 7 | Отменить изменение | Цена восстановлена в копии |
| 8 | Перезагрузить страницу | Локальный журнал восстановлен |
| 9 | Не заполнить основание | Кнопка не должна применять исправление |
| 10 | Повторный импорт исправленного файла в Fin_rez | Расчеты Fin_rez должны выполняться без потери структуры листов |

## Безопасность

Не загружайте необезличенные корпоративные или клиентские отчеты на сторонние сайты и в сторонние средства просмотра HTML. Для корпоративного использования необходимы отдельная проверка разрешений и информационной безопасности.
